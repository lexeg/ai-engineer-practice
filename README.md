# Отчёт по проекту

## Статус аудита

Этот комплект собран из двух архивов с Qwen и OpenRouter и проверен по исходному заданию из `Проект(1).zip`. В README и `outputs/report.json` приведены только подтверждённые результаты. Неизмеренные значения оставлены как `null`, а незавершённые этапы отмечены явно.

## Финальный конфиг

- **Локальная модель:** `Qwen/Qwen2.5-1.5B-Instruct`.
- **Инференс:** vLLM 0.6.6 (версия указана в `logs/vllm.log`).
- **Точность:** FP16 (`--dtype half`).
- **Контекст:** 4096 токенов.
- **Параметры vLLM:** `--gpu-memory-utilization 0.9`, `--enforce-eager`, порт `8000`.
- **Генерация:** `temperature=0.2`, `max_tokens=800`.
- `top_p`, `top_k` и `repetition_penalty` явно не задавались — использовались значения по умолчанию.
- **Повторы при невалидном ответе:** максимум 2 попытки.
- **Лимит входа:** 1500 токенов по токенайзеру Qwen.

Команда запуска:

```bash
nohup vllm serve Qwen/Qwen2.5-1.5B-Instruct --dtype half --max-model-len 4096 \
  --gpu-memory-utilization 0.9 --enforce-eager --port 8000 > vllm.log 2>&1 &
```

В `logs/vllm.log` подтверждены загрузка весов, запуск Uvicorn и успешные ответы `GET /v1/models` со статусом `200 OK`.

## Сравнение с моделью через API

Для OpenRouter найдена тестовая выборка из пяти товаров `P-0027`, `P-0032`, `P-0017`, `P-0021`, `P-0036`. Она является первыми пятью товарами файла `datasets/compare_30.jsonl`, но полный прогон на 20–30 товарах не найден.

| Метрика | Qwen, локально: те же 5 товаров | OpenRouter Particle |
|---|---:|---:|
| Валидные карточки | 5/5 (100%) | 5/5 (100%) |
| Входные токены | 5 747* | 5 573 |
| Выходные токены | 1 006 | 1 073 |
| Средняя latency запроса | не сохранена | 14,967 сек. |
| Общее время | не сохранено | 24,1 сек.** |
| Стоимость на 1000 карточек | не рассчитана | **35,17 ₽** |

\* Локальные входные токены посчитаны токенайзером Qwen; API-токены получены из `usage`. Сравнивать эти числа напрямую некорректно из-за разных токенизаторов.

\** Общее время 24,1 секунды присутствует в ранее сохранённом `report.json`, но не записано в per-card JSONL. Сумма latency пяти запросов составляет 74,836 секунды; при параллельной обработке она не равна общему времени прогона.

**Ограничение сравнения:** системный промпт в архивной версии `run_openrouter.py` отличается от локального `SYSTEM_PROMPT` в `run_batch.py`. Поэтому результаты нельзя считать строгим сравнением моделей на полностью одинаковом запросе. В комплект добавлен `compare_api.py`, который использует локальный системный промпт и параметры локального генератора.

**Ошибки API:** в одном из тестов Particle зафиксирован `429 Rate limit exceeded`. Архивная версия клиента повторяла запрос ограниченное число раз, но не реализовывала экспоненциальную задержку. В новом `compare_api.py` предусмотрены повторы для `429` и `5xx` с задержками 1, 2 и 4 секунды; `400` завершается с диагностикой, так как требует исправления параметров запроса. Ошибки `400` и `5xx` в сохранённых тестах не обнаружены.

Стоимость API рассчитана по условному тарифу задания и фактическому `usage` теста:

```text
((5573 × 20) + (1073 × 60)) / 1 000 000 / 5 × 1000 = 35,17 ₽
```

Это выше целевого ограничения 25 ₽/1000 карточек. Оценка получена на пяти карточках и не является полноценным месячным прогнозом.

## Замеры

### Качество на benchmark

Для `benchmark.jsonl` сохранено 300 результатов при concurrency 16.

| Метрика | Значение |
|---|---:|
| Всего товаров | 300 |
| Валидных по правилам задания | 260 |
| Невалидных | 40 |
| Доля валидных | **86,7%** |
| Среднее число попыток | 1,1767 |
| Входные токены, записанные генератором | 363 884 |
| Выходные токены | 86 528 |

Причины ошибок (количество срабатываний правил; одна карточка могла нарушить несколько правил):

| Причина | Количество |
|---|---:|
| Длина description | 28 |
| Количество предложений | 11 |
| Количество тегов | 2 |
| Некорректный JSON | 3 |

Важное уточнение: `run_batch.py` сохраняет успешные ответы после нормализации. Кроме того, пять записей со статусом генератора `INVALID` всё же содержат карточки, проходящие широкие формальные правила задания. В отчёте валидность считается по содержимому карточки, а не по внутреннему статусу генератора.

Поле `input_tokens` локального генератора считает исходный запрос один раз на товар; токены повторного запроса в эту сумму не добавляются. Поэтому эту сумму нельзя использовать как полный расход prompt-токенов для расчёта стоимости.

### Concurrency

В архивах найдены прогоны на 300 товарах для concurrency 1, 4, 16 и 32. Доля валидных пересчитана по правилам задания.

| Concurrency | Валидных | Доля валидных | Попытка 1 | Попытка 2 | Выходные токены | Время / throughput / latency |
|---:|---:|---:|---:|---:|---:|---|
| 1 | 261/300 | 87,0% | 249 | 51 | 83 402 | не сохранены |
| 4 | 255/300 | 85,0% | 233 | 67 | 87 717 | не сохранены |
| 16 | 260/300 | 86,7% | 247 | 53 | 86 528 | не сохранены |
| 32 | 254/300 | 84,7% | 241 | 59 | 91 846 | не сохранены |

Concurrency 16 использован для итогового файла `outputs/predictions.jsonl`, но по имеющимся артефактам нельзя доказать, что это оптимальная точка по throughput: elapsed и latency не были сохранены.

### Время и стоимость локального сервера

Время полного прогона 300 товаров, средняя latency и throughput в архиве отсутствуют. Поэтому нельзя подтвердить ограничение «не более 8 минут» и нельзя рассчитать стоимость локальной обработки.

Для достижения стоимости не выше 25 ₽/1000 при прогоне 300 карточек время прогона должно быть не более примерно 415,4 секунды:

```text
(t / 3600 × 65) / 300 × 1000 ≤ 25
```

Для сравнения, при времени 480 секунд (8 минут) стоимость составила бы около 28,89 ₽/1000 — выше целевого порога.

## Длинный вход

В `dev.jsonl` есть товары с большим количеством отзывов (до 191), а в `benchmark.jsonl` — до 220 отзывов.

В `run_batch.py` реализованы:
1. удаление типовых вводных фраз;
2. удаление пустых отзывов;
3. дедупликация нормализованных отзывов;
4. фильтрация части отзывов с противоречивыми формулировками;
5. подсчёт входных токенов токенайзером Qwen и проверка лимита 1500.

Максимум после preprocessing в сохранённых прогонах:
- dev: 1440 токенов;
- benchmark: 1446 токенов.

В сохранённых прогонах все входы оказались в лимите. Отдельного усечения отзывов или суммаризации отдельным LLM-запросом нет; если новый товар после preprocessing превысит 1500 токенов, текущий код помечает его как невалидный, а не сокращает автоматически.

## Оптимизации

Использована точность FP16 (`--dtype half`). В `vllm.log` подтверждается `torch.float16`. Сравнение с INT4 в архивах отсутствует, поэтому преимущество FP16/INT4 экспериментально не оценивалось.

## Стоимость и решение

- **OpenRouter:** 35,17 ₽/1000 по пяти фактическим API-ответам. Это выше целевых 25 ₽/1000.
- **Своя ВМ:** стоимость не рассчитана, потому что время полного прогона не сохранено.
- **Порог локальной стоимости:** при 300 товарах время должно быть не более 415,4 секунды, чтобы уложиться в 25 ₽/1000.
- **Плановые 50 000 карточек:** экстраполяция API по тестовой оценке составила бы около 1 758 ₽/месяц, но выборка из пяти карточек слишком мала для окончательного решения.

Точку окупаемости и окончательный выбор между ВМ и API определить нельзя без фактического времени локального прогона и модели использования ВМ (сколько часов в месяц она оплачивается, включая простой).

- `check_metrics.py` — проверка формата по правилам задания.
- `datasets/` — исходные dev, benchmark и compare_30.
- `outputs/predictions.jsonl` — сохранённые результаты Qwen c16.
- `outputs/dev_predictions.jsonl` — dev-прогон c4.
- `outputs/api_predictions_5.jsonl` — сохранённый тест API на пяти товарах.
- `outputs/concurrency/` — результаты четырёх уровней concurrency.
- `outputs/report.json` — сводные подтверждённые метрики и отсутствующие замеры.
- `logs/vllm.log` — лог запуска vLLM.
