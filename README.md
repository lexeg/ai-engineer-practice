# Отчёт по проекту

## Статус аудита

Комплект собран из двух архивов с Qwen и OpenRouter и проверен по исходному заданию.

В README и `outputs/report.json` приведены подтверждённые результаты экспериментов. Неизмеренные значения оставлены как `null`, а незавершённые этапы отмечены явно.

Полный локальный benchmark на 300 товарах выполнен. Время обработки измерено, результат независимо проверен, стоимость локальной обработки рассчитана.

Сравнение локальной модели с API пока не завершено: полноценный прогон на 20–30 одинаковых товарах с идентичным системным промптом не состоялся из-за ограничений бесплатного тарифа OpenRouter.

## Финальный конфиг

- **Локальная модель:** `Qwen/Qwen2.5-1.5B-Instruct`.
- **Инференс:** vLLM 0.6.6 (версия указана в `logs/vllm.log`).
- **Точность:** FP16 (`--dtype half`).
- **Контекст:** 4096 токенов.
- **Параметры vLLM:** `--gpu-memory-utilization 0.9`, `--enforce-eager`, порт `8000`.
- **Генерация в основном benchmark:** `temperature=0.2`, `top_p=1.0`, `top_k=-1`, `repetition_penalty=1.0`, `max_tokens=800`.
- **Повторы при невалидном ответе:** максимум 2 попытки.
- **Лимит входа:** 1500 токенов по токенайзеру Qwen.

Команда запуска:

```bash
nohup vllm serve Qwen/Qwen2.5-1.5B-Instruct --dtype half --max-model-len 4096 \
  --gpu-memory-utilization 0.9 --enforce-eager --port 8000 > vllm.log 2>&1 &
```

В `logs/vllm.log` подтверждены загрузка весов, запуск Uvicorn и успешные ответы `GET /v1/models` со статусом `200 OK`.

Отдельно проведён предварительный эксперимент на 9 конфигурациях с выборкой из 5 товаров на каждую конфигурацию (45 запросов).

Наилучший результат в этом эксперименте показала конфигурация:

Результат — 5/5 валидных карточек.

Это предварительный результат на небольшой выборке, а не доказательство оптимальности конфигурации. Полная сетка из 162 конфигураций не завершена.

## Сравнение с моделью через API

Для OpenRouter найдена тестовая выборка из пяти товаров: `P-0027`, `P-0032`, `P-0017`, `P-0021`, `P-0036`. Она является первыми пятью товарами файла `datasets/compare_30.jsonl`.

| Метрика | Qwen, локально: те же 5 товаров | OpenRouter Particle |
|---|---:|---:|
| Валидные карточки | 5/5 (100%) | 5/5 (100%) |

\* Локальные входные токены посчитаны токенайзером Qwen; API-токены получены из `usage`. Сравнивать эти числа напрямую некорректно из-за разных токенизаторов.

\** Общее время 24,1 секунды присутствует в ранее сохранённом `report.json`, но не записано в per-card JSONL. Сумма latency пяти запросов составляет 74,836 секунды; при параллельной обработке она не равна общему времени прогона.

**Ограничение сравнения:** системный промпт в архивной версии `run_openrouter.py` отличается от локального `SYSTEM_PROMPT` в `run_batch.py`. Поэтому результаты нельзя считать строгим сравнением моделей на полностью одинаковом запросе.

В комплект добавлен `compare_api.py`, предназначенный для сравнительного тестирования OpenRouter с использованием локального системного промпта и параметров генератора. Однако полноценный сравнительный прогон пока не завершён.

- Невалидных результатов — 18.

Этот запуск показал проблему с ограничением длины генерации. Его результаты не используются как окончательная оценка качества модели.

**Вторая попытка:**

Для повторного теста было увеличено ограничение генерации до `max_tokens=2000`.

Этот запуск не является оценкой качества модели: генерация фактически не состоялась из-за ограничения бесплатного тарифа OpenRouter.

**Повторная проверка:**

После этого был выполнен ещё один запуск `compare_api.py` на тех же 30 товарах с `concurrency=4`, `max_attempts=2` и `max_tokens=2000`.

Результат повторного запуска:

| Метрика | Значение |

| Валидных карточек | 0 |
| Невалидных карточек | 30 |
| Доля валидных | 0% |

При проверке сохранённых результатов для нескольких товаров обнаружена одна и та же ошибка:

Таким образом, причина сбоя подтверждена текстом исключений: исчерпана дневная квота бесплатных моделей OpenRouter.

Полученный throughput `0,323 карточки/сек.` отражает обработку неудачных запросов и ожидание повторных попыток. Он не характеризует скорость генерации модели и не используется для сравнения производительности Qwen и Particle.

Этот повторный запуск также не является оценкой качества модели: генерация не состоялась, токены не расходовались.

### Обработка ошибок API

В одном из тестов Particle зафиксирован ответ `429 Rate limit exceeded`.

Архивная версия клиента повторяла запрос ограниченное число раз, но не реализовывала экспоненциальную задержку.

В новом `compare_api.py` предусмотрены повторы для `429` и `5xx` с задержками 1, 2 и 4 секунды. Ошибка `400` завершается с диагностикой, так как обычно требует исправления параметров запроса.

Ошибки `400` и `5xx` в сохранённых тестах не обнаружены.

Повторные запросы с backoff помогают при временных ограничениях частоты запросов и временных ошибках сервера. Однако при исчерпании дневной квоты `free-models-per-day` они не позволяют продолжить генерацию. В таком случае необходимо дождаться восстановления квоты.

### Расчёт стоимости API

Стоимость API рассчитана по условному тарифу задания и фактическому `usage` теста на пяти товарах:

```text
((5573 × 20) + (1073 × 60)) / 1 000 000 / 5 × 1000 = 35,17 ₽
```

Полученная оценка выше целевого ограничения 25 ₽/1000 карточек.

Это предварительный результат на пяти карточках. Он не является полноценным месячным прогнозом и не должен рассматриваться как окончательная стоимость API при обработке большого объёма товаров.

Запуски на 30 товарах, завершившиеся ошибками квоты, в расчёт стоимости не включаются: фактическая генерация не состоялась, количество обработанных токенов равно нулю.

#### Количество попыток генерации

По результатам полного прогона 300 карточек:

| Показатель | Значение |
|---|---:|
| С первой попытки | 233 |
| Потребовали повторной попытки | 67 |
| Успешны после повтора | 10 |
| Остались невалидными | 57 |
| Среднее количество попыток | 1,223 |

Среднее количество попыток рассчитано по полю `attempt` в результатах генерации:

```text
(233 × 1 + 67 × 2) / 300 = 1,223
```

Индивидуальная latency запросов в данном прогоне не сохранялась. Поэтому средняя latency отдельной карточки не приводится.

Для оценки производительности используется полное время процесса — 218,24 секунды — и throughput 1,374 карточки/сек.

#### Стоимость локальной обработки

Для расчёта используется ставка 65 ₽/час и фактическое полное время обработки:

```text
(218,24 / 3600 × 65) / 300 × 1000 = 13,13 ₽
```

**Итоговая расчётная стоимость — 13,13 ₽ на 1000 карточек.**

Это расчёт стоимости вычислений за время обработки. Он предполагает, что ВМ оплачивается только за фактическое время работы над задачей.

Расчёт не учитывает возможный минимальный оплачиваемый интервал аренды ВМ, время запуска модели, простой между заданиями и дополнительные расходы на инфраструктуру.

Если сервер арендуется постоянно, необходимо учитывать оплату простоя.

Средняя latency отдельного запроса не зафиксирована. Полное время процесса, делённое на количество карточек, характеризует производительность всего запуска, а не latency отдельного запроса.

## Длинный вход

В `dev.jsonl` есть товары с большим количеством отзывов (до 191), а в `benchmark.jsonl` — до 220 отзывов.

В `run_batch.py` реализована адаптивная предобработка длинных входных данных:

1. удаление типовых вводных фраз;
2. удаление пустых отзывов;
3. дедупликация нормализованных отзывов;
4. фильтрация части отзывов с противоречивыми формулировками;
5. отбор не более 7 уникальных отзывов;
6. подсчёт входных токенов токенайзером Qwen;
7. последовательное сокращение списка отзывов до достижения лимита 1500 токенов.

Название, категория и технические атрибуты товара сохраняются. При сокращении входа удаляются отзывы, а не характеристики товара.

### Результаты предобработки

На выборке из 40 товаров `dev.jsonl` получены следующие результаты:

| Метрика | До обработки | После обработки |
|---|---:|---:|
| Среднее количество токенов | 1962,5 | 1417,1 |
| Максимальное количество токенов | 5295 | 1460 |
| Товаров выше лимита 1500 токенов | 24 | 0 |

Средний размер входа сократился на 27,8%. Все 40 товаров после предобработки укладываются в установленный лимит.

Предобработка не гарантирует сохранение всей информации из отзывов: при необходимости часть отзывов отбрасывается. Отдельная LLM-суммаризация отзывов не используется.

## Оптимизации

Использована точность FP16 (`--dtype half`). В `vllm.log` подтверждается `torch.float16`.

Сравнение с INT4 в архивах отсутствует, поэтому преимущество FP16/INT4 экспериментально не оценивалось.

## Стоимость и решение

### Сравнение стоимости

| Вариант | Стоимость на 1000 карточек | Ограничения оценки |
|---|---:|---|
| Локальная Qwen на ВМ | **13,13 ₽** | Расчёт при оплате только времени обработки |
| OpenRouter Particle | 35,17 ₽ | Предварительный тест на 5 карточках с отличавшимся системным промптом |

Локальная стоимость рассчитана по фактическому времени полного прогона 300 карточек. Стоимость OpenRouter рассчитана по фактическому `usage` пяти тестовых запросов и тарифам задания.

Сравнение пока не является окончательным: для API необходимо провести тест на 20–30 карточках с тем же системным промптом, который используется локально.

### Точка безубыточности при постоянной аренде ВМ

Для оценки рассмотрим два сценария:

1. ВМ оплачивается только за время обработки.
2. ВМ арендуется круглосуточно, независимо от нагрузки.

При постоянной аренде по ставке 65 ₽/час месячная стоимость ВМ при условных 720 часах составит:

```text
65 × 720 = 46 800 ₽/месяц
```

При предварительной стоимости API 35,17 ₽ на 1000 карточек точка безубыточности:

```text
46 800 / 35,17 × 1000 ≈ 1 330 680 карточек/месяц
```

При объёме 50 000 карточек в месяц:

| Вариант | Расчётная стоимость в месяц |
|---|---:|
| OpenRouter | 1 758,50 ₽ |
| Постоянная аренда ВМ | 46 800 ₽ |

Если ВМ оплачивается круглосуточно и используется только для этой задачи, API по предварительным тарифам экономически выгоднее при объёмах ниже примерно 1,33 млн карточек в месяц.

Если же ВМ уже арендована и используется для других задач либо оплачивается только время обработки, локальный вариант может оказаться выгоднее.

**Предварительный вывод:** локальная модель выполнила ограничение по времени и показала расчётную стоимость ниже 25 ₽/1000 карточек при оплате только времени обработки. Окончательный выбор между локальной ВМ и API требует полноценного сравнения на одинаковых запросах и учёта режима аренды сервера.

Расчёт точки безубыточности предварительный: стоимость API пока основана на выборке из пяти карточек.

- Подготовка клиента для сравнительного тестирования OpenRouter с локальным системным промптом.
- Повторная проверка ошибки OpenRouter на 30 товарах; причина `429 free-models-per-day` подтверждена текстом исключений.

## Структура комплекта

- `run_batch.py` — локальная генерация.
- `run_batch_benchmark.py` — запуск benchmark.
- `run_parameter_experiments.py` — полный перебор конфигураций генерации (162 конфигурации; полный прогон пока не завершён).
- `run_parameter_experiments_small.py` — сокращённый предварительный эксперимент на 9 конфигурациях.
- `compare_api.py` — клиент OpenRouter, предназначенный для сравнения с локальной моделью с использованием того же системного промпта; предусмотрены retry/backoff для 429/5xx.
- `check_metrics.py` — проверка формата по правилам задания.
- `datasets/` — исходные dev, benchmark и compare_30.
- `outputs/predictions.jsonl` — сохранённые результаты Qwen c16.
- `outputs/dev_predictions.jsonl` — dev-прогон c4.
- `outputs/api_predictions_5.jsonl` — сохранённый тест API на пяти товарах.
- `outputs/api_predictions_30_v2.jsonl` — результаты повторного тестирования API на 30 товарах; запросы завершились ошибкой дневной квоты OpenRouter.
- `outputs/concurrency/` — результаты четырёх уровней concurrency.
- `outputs/timed/benchmark_c16.jsonl` — результаты нового полного benchmark на 300 товарах.
- `outputs/report.json` — сводные подтверждённые метрики и отсутствующие замеры.
- `logs/benchmark_c16.log` — лог нового benchmark и замеры времени.
- `logs/api_compare_30_v2.log` — лог повторного тестирования OpenRouter на 30 товарах.
- `logs/vllm.log` — лог запуска vLLM.
